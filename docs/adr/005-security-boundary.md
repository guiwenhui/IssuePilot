# ADR-005：仓库、命令与副作用安全边界

- Status: Accepted
- Date: 2026-08-13

## Context

IssuePilot 将读取外部仓库，并在后续阶段修改文件、执行测试。仓库内容和用户输入都不可信；允许模型直接拼接任意 Shell、修改来源仓库或执行 Git 远程写操作，会产生数据破坏、凭据泄露和命令注入风险。

## Decision

MVP 采用以下硬边界：

- 只接收公开仓库 HTTPS URL，并在 M2 增加协议、主机、重定向、仓库大小和路径校验。
- 克隆到受控隔离目录；M7 在临时 Git Worktree 中应用本地 Patch 和测试，绝不修改用户原仓库。
- 测试只允许一个 `pytest` 白名单命令族，默认命令为 `pytest`。参数必须结构化校验，不能把用户文本拼接给 Shell。
- 应用 Patch 和执行测试前需要人工批准；修改范围超出已批准计划时再次暂停。
- 不 Commit、不 Push、不创建真实 PR，不自动执行数据库变更。
- 失败采用分类、有限重试、证据持久化和人工升级，不无限修复。
- 公开演示不得使用公司代码、内部 Issue、私有 GitLab 数据或内部 Skill 源码。

这些能力分别在 M2、M6 与 M7 落地；M0 只记录边界。

M2 的实际实现进一步收紧为：

- 只接受 `https://github.com/{owner}/{repo}`，拒绝凭据、显式端口、Query、Fragment、编码路径分隔符和重定向。
- 使用 argv 调用 Git，不经过 Shell；关闭凭据提示、系统/全局 Git 配置和 LFS smudge。
- 使用 `--depth=1 --single-branch --no-tags --no-recurse-submodules`，Submodule 只作为 Manifest 条目。
- 先写 UUID staging，成功验证后原子移动；清理函数只接受 staging 根目录的直接子项。
- 限制超时、工作区体积、tracked entry 数和路径深度；枚举和计量不跟随符号链接。
- 仓库内容只展示，不导入、不解析、不执行。

M3 允许“解析但不执行”：父进程只把 Git tracked 普通 `.py` 交给固定 argv Python 子进程；Runner 不接收 URL 或数据库凭据，不 Import 仓库模块，不跟随 symlink，并受文件数、字节、条目与墙钟时间限制。解析产物通过受限 JSON Schema 返回，异常摘要截断后持久化。

## Alternatives

### 在主工作目录直接修改

优点是实现简单。缺点是可能污染或破坏用户现有文件，回滚边界不清晰。

### 允许任意 Shell 命令

优点是兼容更多仓库。缺点是命令注入和副作用不可接受，也无法形成可审计的权限模型。

### 自动 Commit、Push 和创建 PR

优点是交付链更完整。缺点是会把模型错误扩散到远程系统，并超出学习型 MVP 的授权范围。

### 仅依赖 Prompt 约束

优点是开发成本低。缺点是 Prompt 不是可靠安全边界，不能替代参数校验、隔离目录、命令白名单和人工审批。

## Consequences

- 支持的仓库和测试方式有限，但行为更可预测、可审计。
- Worktree 与命令执行层需要独立测试路径逃逸、重复执行和超时。
- 新增命令、语言或 Git 远程写能力必须通过新的架构与安全评审，不能作为普通配置悄悄放开。
- 用户看到的是本地 Patch 与执行证据，最终远程交付继续由人工完成。
